## 一、这类画面是怎么做出来的

关键在于：**它不是一个 3D 场景，而是「一张会动的画」**。除了云和车，其余全是画上去的贴图。
逐层拆开看：

### 1. 正交俯视相机 + 镜头一路向北推进

相机从正上方往下看（`OrthographicCamera`，`up = (0,0,-1)`），所以路等宽、树不会倒、云不会被透视拉歪。

**镜头不是静止的**：它以 5.6 个世界单位/秒的速度持续向北（-z）推进（一屏约 14 秒），纸张窗口固定不动，
所以地图整体以 0.14 屏高/秒的速度向下卷 —— 这就是原作「跟着飞机往前飞」的感觉。

地面因此不是一张方图，而是一张 **100 × 232 单位的长条贴图**（约 3 屏长），
镜头在里面从南端走到北端约 13 秒；走到头会退回纸面（白屏一瞬间）再从南端开始。

调过一轮：参考视频实测是 118 px/s（≈11.2 单位/秒），但那个节奏偏「飞」；
治愈向要更慢，所以落在 **5.6 单位/秒**（一屏 14 秒）。改 `CAM_SPEED` 一个常数就能调。

### 2. 地面 = Canvas2D 画出来的一张贴图

`src/ground.js` 里用 2048×2048 的 canvas 逐层叠笔触：

1. 铺底色（`#FA8A33`，这个值是从参考图里采样出来的）
2. 大/中/小三层软色斑（`blob()`，径向渐变 + 低透明度）
3. 几千笔短笔触（`paintBrushes()`），方向统一带随机偏移 —— 这就是「油画/水彩」质感的来源
4. 颜料颗粒（`paintSpeckle()`）
5. 公路、土路、车辙、扬尘直接画进同一张图里，不是几何体

公路这样画：

```js
softStroke(g, road, roadW * 1.5, 边缘尘, 0.12, 2.4);  // 外层晕开
softStroke(g, road, roadW,       路面色, 0.96);        // 实心路面
// 再沿路撒几百个尘土点
```

好处是路和地面的交界天然是「画」出来的，不会有 3D 模型贴片那种硬边。

整张图最后统一 `blur(0.8px)`，让笔触融在一起。

### 3. 树 = InstancedMesh + 程序化树冠 + 同形状影子

- 树冠在 `src/sprites.js` 里生成：先按 3~4 条低频正弦拼出一个不规则闭合轮廓，填实，
  再用 500 多个小圆点（按「左上受光」挑浅/中/深三个绿色）在轮廓内叠出叶面的斑驳 —— 
  所以边缘是碎的、内部是花的，而不是一堆圆球。
- 三种树冠纹理随机分配给 ~100 个实例（`InstancedMesh`），每个实例随机旋转/缩放/色偏。
- 影子：把**同一张树冠纹理**缩小到 128、模糊、染成褐色 → `makeShadowFromCanopy()`，
  按光照方向偏移绘制。所以影子形状天然和树冠一致，而不是一个椭圆。
- 位置用「抖动网格 + 低频噪声控制疏密」采样，避开道路和水面（`scatterTrees()`）。

### 4. 云 = 一片 quad + 片元着色器里的 fbm

`src/shaders.js` 的 `cloudFragment`：把 fbm 噪声当成「云团的距离场」，

```glsl
float shape = r + (0.5 - detail) * 1.06;   // 半径 + 噪声 = 不规则菜花轮廓
float a = smoothstep(0.84, 0.62, shape);   // 很软的透明边缘
vec3  col = vec3(1.0);                     // 纯白，靠 alpha 让下面的赤土透上来
```

要点：
- 云是**平面**（正交俯视下平面就够了），每朵云一个 mesh，`depthTest: false`。
- 边缘的灰/暖不是画进去的，是半透明白色盖在橙色地面上混出来的。
- 噪声随时间极慢平移，云会缓慢「翻涌」。
- 每朵云下面还有一块同噪声的低透明度暗块 = 云的投影，偏移方向和树的影子一致。

### 5. 撕纸边 = 一个后期合成 pass

场景先渲染到 RenderTarget，再用 `compositeFragment` 贴到「纸」上：

```glsl
float d = max(|px - center| - half);          // 到方块边的距离
float edge = d + (n1-0.5)*16 + (n2-0.5)*4.2 + (n3-0.5)*1.4;  // 三段噪声＝大缺口＋毛刺
float mask = smoothstep(1.1, -1.1, edge + (n4-0.5)*2.4);      // 1~2px 的硬边
float fiber = smoothstep(5.0, -2.0, edge) * smoothstep(0.42,0.68, n4);  // 纸纤维
mask = max(mask, fiber);
```

再叠：纸边颜料更暗更饱和的一圈、纸纤维点、少许颗粒。
因为是在**最终画面**上做遮罩，所以地面、树、云会被同一圈撕边一起裁掉 —— 这正是参考图里
「云被纸边切断」的效果来源。

### 6. 颜色管理

```js
THREE.ColorManagement.enabled = false;
renderer.outputColorSpace = THREE.LinearSRGBColorSpace;
```

关掉色彩管理，canvas 上画成什么颜色，画面里就是什么颜色（省掉 sRGB 来回转换的偏差）。
配色不是猜的：把参考图量化成 12 色，量出土色 `#FA8A33 / #FD973C / #D26826`、纸 `#FFFFFF`、
云 `#F5F6F9`，再写进 `src/scenes.js`。

### 7. 场景切换

切场景时先让合成层的 `uReveal` 从 1 淡到 0（退回纸面），重建内容，再淡回 1。
所以是「一页纸翻过去」而不是闪切。

### 8. 飞机穿过云层（云按物理「被推开」）

飞机是一个贴图平面，飞在云层上方（y=80），沿一条带弧度的直线横穿画面、循环往复。

难点是「云散开」。做法是给云着色器传一条**航迹**：

```js
// 每 0.07s 记录一次飞机位置，最多 12 个采样点（约 1.4 秒的航迹）
this.wakeArray[i].set(x, z, 半径, 强度);   // 强度 = (1 - 年龄/1.4)^1.5
```

云着色器把世界坐标和每个采样点比距离：

```glsl
float infl = smoothstep(w.z * lobed, w.z * 0.30 * lobed, dist) * w.w;
hole = max(hole, infl);     // 洞
push += infl;               // 被挤开的量
float a = smoothstep(0.84, 0.62, shape);
a *= 1.0 - hole * 0.97;     // 中间掏空
shape -= push * 0.12;       // 四周的云被挤厚、边缘外扩
```

三个细节让它是「散开」而不是「擦掉」：

- `lobed` 用正弦给洞的边缘加瓣状起伏，边界不会是个正圆；
- `turb` 把云的噪声坐标往四周推开，洞周围出现轻微湍流；
- 强度随年龄平方衰减、半径随年龄收缩 → **航迹会自己合拢**，像真实云层回填。

飞机还有一块随光偏移的软影子落在地面上，所以它「在上面飞」这件事成立。

### 9. 草地上的牛羊

牛羊同样是 canvas 画的俯视贴图（身体 + 头 + 耳朵 + 露出来的腿 + 朝向受光面），
每只按一条李萨如轨迹慢慢晃：

```js
x = cx + cos(t) * rx;
z = cz + sin(t * 0.8) * rz;   // 两个不同频率 → 走起来不像圆周运动
```

朝向取速度方向，再加一个呼吸式的身体缩放当作走路的起伏。
出生点复用树的那套采样（避开河和路），所以牛羊不会站在水里。

### 10. 车走各自车道

对向车如果都压中线会穿模。公路每个点都存了法线：

```js
const [nx, nz] = this.roadNormals[i0];
mesh.position.x = x + nx * lane * dir;   // lane = 1.15，dir = ±1
```

所以两辆车分居中线左右各 1.15 个单位（路总宽 4.5，正好一条车道），
对向会车时是「擦身而过」而不是重叠。

## 二、文件结构

```
index.html          画面外的一切：导航、标题、字体、留白
src/main.js         渲染器 / 正交相机 / 合成 pass / 实例化 / 动画循环
src/ground.js       地貌绘制（四个场景的画法）+ 树的采样
src/sprites.js      树冠、影子、小汽车 —— 全是 canvas 生成
src/shaders.js      云的着色器 + 撕纸合成着色器
src/scenes.js       四个场景的色板、文案、树/云参数
shot.mjs            无头浏览器截图（调试用）
```

## 三、想改的话

- **换配色**：`src/scenes.js` 的 `paint.base / mottle / patch / highlight`。
- **树更密/更疏**：`trees.minDist`（网格间距，数值越小越密）、`scale / bigScale`（尺寸范围）。
- **云更大/更实**：`clouds.sizes`、`clouds.layout`（按画框 0~1 摆位），着色器里调
  `smoothstep(0.84, 0.62, shape)` 的两个端点（越接近，边缘越硬）。
- **撕纸边更碎**：`compositeFragment` 里 `n1` 的幅度（现在 16px）。
- **飞机航线/速度**：`applyScene` 里的 `planePath`（x0/z0 → x1/z1 + 弧度 + speed）。
- **云被推开的范围**：`tick()` 里的 `3.8 + 4.0 * life`（洞的半径）和 `1.4`（航迹存活秒数）。
- **牛羊数量**：`src/scenes.js` 里 `animals: { cows, sheep }`。
- **车道宽度**：车对象上的 `lane`。

## 四、和原作差在哪

技术路径一致（正交俯视 + 贴图画地面 + 实例化植被 + 着色器云 + 后期撕纸遮罩），
但**素材是程序生成的，不是原站那张手绘**：

- 原站的树/纸/云很可能是美术手绘或更高成本的资产；本复刻的树冠、笔触都是随机生成的，
  构图分布不可能和原图逐像素对齐。
- 云的体积感来自 alpha 渐变，不是体积云；贴着看是「一片白」而不是有厚度的云。
- 树没有真正的光照模型，受光方向是烘焙在贴图里的。

要「一模一样」，缺的是原站的艺术资产（树冠/地面手绘稿），而不是技术。

## 比例是量出来的

对着视频逐帧量（艺术块 825 px = 78 世界单位，即 10.6 px/单位），
所有物件尺寸都按实测值重设：

| 物件 | 参考视频 | 本复刻 |
| --- | --- | --- |
| 公路宽 | ~5 单位 | 5.0 |
| 车长 | ~3.5 单位 | 3.6 |
| 飞机翼展 | ~4.7 单位 | 4.7 |
| 树冠 | 2.6–5 单位 | 2.4–5.3 |
| 牛羊 | 0.7–1.7 单位 | 0.9–1.7 |
| 镜头推进 | 11.2 单位/秒 | 5.6（刻意放慢） |

地面「颗粒感」也来自实测：参考画面里密布的小灌木/碎石是**画进贴图的**
（每屏几百个，1–4 px），不是 3D 物件；所以 `paintBase` 里专门有一层
带小影子的植被点（`bush` / `bushShadow`）。

## 飞机用的是你提供的程序化模型

`src/airplane.js`（来自 `threejs-island-plane.zip`）是纯 Three.js 几何体拼的单引擎螺旋桨飞机：
机身胶囊体 + 梯形主翼 + 尾翼 + 青色座舱罩 + 舷窗 + 机翼条带 + 会转的螺旋桨 + 简化起落架。

集成方式：

- 模型**机头朝 +Z**，本项目约定机头朝 −Z，所以外面套一层 `holder` 并把内层 `rotation.y = Math.PI`；
- 缩放到翼展 **4.8 世界单位**（`scale = 4.8 / 2.04`），和视频里实测的 4.8 一致；
- 全场只有飞机用实体材质，所以在 `applyScene()` 里给它配了一盏平行光（方向与树影一致：
  光从左上来）加一盏半球光，别的地方仍然是平的 `MeshBasicMaterial`；
- 飞机飞在云层之上（y = 92），开 `depthTest` 让模型自身前后正确遮挡，
  `renderOrder = 12` 保证它画在云之上；
- 每帧调用 `airplane.update(dt)` 转螺旋桨，地面上的软影子仍用和树影同一套贴图。

注意：灯光必须建在 `applyScene()` 里而不是构造函数里 —— `clearScene()` 会清掉场景所有子节点，
建在构造函数里的灯第一帧就被删了（第一版飞机因此是纯黑剪影）。

## 鼠标接管飞行 / 偶尔翻滚 / 云量

**鼠标进画框就接管飞机。** 正交相机下屏幕→世界是线性映射，所以直接：

```js
const tx = camera.position.x + ndc.x * halfW;
const tz = camera.position.z - ndc.y * halfH;   // 屏幕上方 = −z
desired = Math.atan2(tx - planeX, -(tz - planeZ));   // 朝北为 0
```

然后按**限速转向**（2.0 rad/s）转向目标，速度随距离收缩（3–9 单位/秒），
所以它飞向鼠标、到跟前减速绕圈，而不是原地打转。
鼠标移出画框后自动切回「沿公路向北 + 轻微摆动」的默认航线（用 0.3 的系数慢慢并回去，
不会突然拐弯）。

**翻滚：自动 + 手动。**

- 自动：每 9–24 秒随机来一次（方向也随机）
- **左键 = 顺时针翻滚，右键 = 逆时针翻滚**（`contextmenu` 已屏蔽，右键不会弹菜单）

桶滚绕机身纵轴转 2π，用 smootherstep 缓入缓出（1.3 秒），同时抬高 2.2 单位；
轨迹还会朝翻滚的反侧划出去 2.6 单位 —— 这样左滚和右滚在画面上才看得出区别，
不然一个左右对称的飞机从正上方看，两个方向几乎一样。
因为是正俯视，滚到 90° 时翼展正好被压成一条线，这个瞬间最好认。

> 调试用：`window.__app.debugRoll = 1.57` 可以锁住任意滚转角。

**云量。** 每个场景 22–28 朵（之前 11–14），横向铺在画框里、少数甩到边外被纸边切断。
云是普通 `Mesh`，所以开了**视锥剔除**：只有进画面的那 7–8 朵才跑昂贵的云着色器；
再加 `uWakeActive` 开关，离航迹远的云直接跳过 12 次循环，影子的噪声也从 5 阶降到 3 阶。
实测仍然 60fps。

## 四个场景的地貌：配色都是从视频里量出来的

其他三个场景重画过一轮 —— 原来的配色偏灰、偏「雾」，和视频里那种**鲜亮、色块分明**的插画感差得远。
办法还是量化：把视频里每个场景的艺术区抠出来做中位切分，取前 8 个主色当色板。

| 场景 | 视频主色（实测） | 地貌结构 |
| --- | --- | --- |
| 草原河流 | `#AAD317` 亮黄绿、`#327461` 深青 | 亮黄绿草甸 + 深青的河 + **两圈沙岸** + 岸边成排的树 + 河里白石头 + 左侧土路 |
| 蓝金田野 | `#FBDB1B` 鲜黄、`#0590F7` 鲜蓝、`#40A46D` 绿 | 鲜亮色块 + **田埂树篱**（深绿带 + 一排小树）+ 穿过田野的河 + 池塘 + 小白房子 |
| 碧海沙洲 | `#75E4D4` 薄荷青、`#25D2D7`、`#EEEACE` 奶白 | 薄荷青潟湖 + 渐变的**浅滩环** + 浪花碎弧 + 深蓝水道 + 带绿植的沙洲小岛 |
| 赤土荒野 | `#FA8A33` 亮暖橙 | 见前文 |

草地重画后的实测对比：视频 `#aad317`（色相 73、饱和 0.80），复刻 `#a5ca2b`（色相 74、饱和 0.65）——
色相一致，饱和度略低一点，代码里再微调过一轮。

河边成排的树是**画进贴图**的（`paintRiver` 里沿河岸撒 900 个带影子的绿点），
而不是实例化模型 —— 这样树才会贴着岸线长，不会乱跑到草地中间。

## 最后一轮：潮滩地形 + 慢翻滚 + 宫崎骏式的柔暖

**沙洲改成海沙交错。** 原来只是「左沙右水」一条分界线，现在是：
三条不同相位的**潮水水道**（各自带浅滩环 → 水体 → 深槽 → 浪花）+ 16 个**潟湖**
（水面外一圈浅滩、再加一道白浪环），水与沙互相穿插，中间夹着被潮水磨圆的沙洲；
沙地上还压了 2600 道细弧线当**退潮潮痕**，外加小石头和贝壳。
树会避开所有水面 —— `exclude()` 现在同时判水道（最近距离）和潟湖（椭圆内外）。

**翻滚放慢。** 一圈从 1.3 秒拉到 **2.4 秒**，抬升和横向划出的幅度没变，
所以是"慢慢翻过去"，而不是"打个滚"。

**画风向宫崎骏靠。** 手绘感主要靠合成这一步（`compositeFragment`）：

```glsl
col *= vec3(1.0, 0.976, 0.945);                 // 整体罩一层暖光
col = mix(vec3(lum), col, 0.93);                // 轻微去饱和，不要电子色
vec2 vq = vUv - 0.5;
col *= 1.0 - 0.13 * dot(vq, vq) * 3.4;          // 极淡的暗角
col = mix(col, vec3(1.0, 0.992, 0.972), 0.045); // 往暖白里掺一点
```

外加地面贴图的收尾柔化从 0.7px 提到 1.1px（笔触融在一起，更像水彩）、
纸面颗粒加重一点、云的暗部颜色从偏冷的灰蓝改成偏暖的米灰。

## 阴影：飞机改用真实阴影贴图（修了两个 bug）

原来飞机的影子是「一张偏移的软椭圆贴图」，很假。改成真的投影：

- `renderer.shadowMap.enabled` + `PCFSoftShadowMap`
- 一盏**只负责投影的太阳**，每帧跟着镜头走（阴影相机 ±55、2048 贴图）
- 地面叠一块 `ShadowMaterial` 承接面 —— 只画影子不画材质，地面贴图不受影响
- 飞机模型本来就有 `castShadow = true`，现在真的生效

修的两个 bug：

1. **阴影相机的 far 只有 300，而光源放在 520 高** —— 地面压根不在视锥里，所以投影是空的。
   far 改成 900（或者把光源放低）就好了。
2. **影子方向反了**：SUN 指向右下，光源却放在 `+SUN` 一侧，投出来的影子跑到飞机**左上**了，
   和树影、云影的方向（右下）正好相反。光源改到 `-SUN` 一侧后，三者的光向才一致。

`normalBias` 也从 0.6 降到 0.05 —— 对一架只有 5 个单位的飞机来说 0.6 太大，会把薄几何体的影子抹掉。

**树影仍然是烘焙贴图**（树冠形状的褐色软影，偏移绘制），不是阴影贴图投的。
形状和方向对，但没有真实投影几何；让上千个 alpha 贴片参与投影成本高、且 alphaTest 出来的轮廓更硬。

## 云与飞机影子的交互：云会挡住飞机的影子

之前两套影子各画各的，飞机钻进云里影子照样落在地上，不对。
现在按「云有多厚」调制地面承接面的不透明度：

```js
for (const c of this.clouds) {
  const qx = (planeX - c.mesh.position.x) / c.size * 2;
  const qz = (planeZ - c.mesh.position.z) / c.size * 2 * 1.12;
  const a = 1 - smoothstep(hypot(qx, qz), 0.52, 0.96);   // 和云着色器同一套轮廓
  cover = Math.max(cover, a);
}
catcher.material.opacity = 0.34 * (1 - 0.92 * (cover - 0.18));
```

- **云心**：`cover ≈ 1` → 影子几乎完全被云挡掉（实测 0.084 / 0.34）
- **云边**：`cover` 在 0.52–0.96 之间过渡 → 只有**一部分**影子透出来
- **云外**：`cover = 0` → 影子完整（实测 0.34）

那个 `- 0.18` 是补「云被飞机拨开的洞本来就漏光」这件事：破洞处少挡一点，
所以飞机刚穿过云时，影子会从还没合拢的缺口里透出来。
云的**自身投影**用的是同一个云着色器，所以破洞同样会出现在云影上 —— 两套影子在同一个洞里对齐。

## 无限循环：世界在 z 方向是个环

之前长条只有 232 单位，镜头走到头会**退回纸面再从南端开始**（每 26 秒闪一下白）。
现在没有"到头"这件事了：

- **贴图首尾无缝**：地面画完后，取顶部 11% 和底部 11% 做交叉渐变（到边界处两边像素完全一致），
  于是贴图可以上下相接（`wrapT = RepeatWrapping`，平面高度做成两个周期）。
- **植被按周期复制**：树/灌木在采样时，把距上边界和下边界 62 单位内的点各复制一份到对面
  （`scatterPoints(..., wrap: 62)`），所以整体平移一个周期时分布也对得上。
- **地面和植被跟着周期走**：每帧把地面和植被的 `position.z` 对齐到 `round(camZ / LOOP) * LOOP`，
  平移量永远是整数个周期，画面上看不出来。
- **动的物件绕回来**：云、飞机、牛羊每帧做一次 `wrapRel()` —— 保持在相机 ±半个周期内，
  越过边界时在**画面外**绕回来，所以飞机永远在飞，不会"重来"。

实测（把飞机冻结后对比）：

| 走过 | 与起点的画面差异（0–255） |
| --- | --- |
| 1 个周期 | 3.5 |
| 4 个周期 | 5.1 |

差异全来自云的自行漂移和细节纹理，没有累计漂移；`revealTarget` 也确认是"无停顿"状态 ——
那 26 秒一次的白闪彻底没有了。
